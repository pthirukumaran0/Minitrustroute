1. Project Identity & Technical Foundation

Core Objective: Traditional financial payment routing focuses almost exclusively on finding a reachable pathway between banking endpoints. However, it fails to dynamically integrate real-time transaction risk, telecom-level identity indicators, and live network degradation into routing decisions. TrustRoute bridges this gap by unifying transaction risk assessment, telecom identity signals (CAMARA Open Gateway), and graph-based multi-path alternative calculation (Yen's K-Shortest Paths algorithm) into an integrated enterprise solution.

Key Academic & Technical Honesty Note: TrustRoute is an integrated proposed solution. CAMARA telecom APIs are operated via an enterprise-grade mock service demonstrating SIM Swap, Device Swap, and Location Verification. Yen's algorithm calculates true loopless alternative routes across a shared Neo4j topology. All transaction, user, and audit data are persisted in live MongoDB instances.

5. Evaluator Defense: Technical & Algorithmic Deep Dive

How Yen's K-Shortest Paths Algorithm Works in TrustRoute

In standard payment networks, simple Dijkstra or A* algorithms only produce the single cheapest or fastest route. If that rail fails or suffers latency spikes, transactions stall. TrustRoute implements Yen's K-Shortest Paths Algorithm on top of Neo4j to compute K loopless alternative pathways:

  • Step 1 (Root Shortest Path): Uses Dijkstra's algorithm to determine the global shortest path \( A_1 \) between source bank \( S \) and destination bank \( D \) using composite edge weights \( W(e) = \alpha \cdot \text{Cost} + \beta \cdot \text{Latency} + \gamma \cdot \text{Risk} \).
  • Step 2 (Spur Node Iteration): For finding the \( k \)-th path (\( 2 \le k \le K \)), the algorithm iterates through each node in path \( A_{k-1} \) as a spur node. Edge costs previously used are temporarily masked to prevent duplicate sub-paths.
  • Step 3 (Candidate Heap): A spur path is computed from the spur node to the destination, concatenated with the root path, and stored in a candidate priority queue \( B \).
  • Step 4 (Loopless Selection): The lowest-cost loopless path from \( B \) is extracted as \( A_k \). This guarantees mathematically distinct alternative routes ready for failover.
